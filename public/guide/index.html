Step-by-step guide

How Beach Day was built and put on the web, in order.

Steps 5 to 12 need your own Supabase and Netlify accounts. At the time of writing no live site is linked, so this guide does not point to one.

  1. Write the design first

    Decisions live in docs/: use case and scoring, the installable app, Netlify, Agents, the Claude API and testing. Short decision records sit in docs/adr/. Start with docs/README.md.

  2. Set up the agent team

    Twelve specialist agents live in .claude/agents/, with shared skills in .claude/skills/. Each agent has its own knowledge folder in knowledge/. One agent, the orchestrator, plans the work and passes it between the others.

  3. Build in waves

    Wave 0 lays the npm and test foundation. Wave 1 builds the pieces that do not depend on each other, in parallel. Each wave ends with read-only reviews by the experts whose area the change touches, and owners fix only the required items. Wave 2 builds screens and handlers on top. Wave 3 is the full test run, the local run and the final security review. Wave 4 fixes what they found.

  4. Prove it locally

    Install, run the unit tests, then the phone-sized browser tests:

    npm ci
npx vitest run
npx playwright test --trace off

    Serve the whole site on your computer with fake sign-in, Claude and GitHub services, so nothing real is called:

    node tests/harness/server.mjs

    Then open http://127.0.0.1:4173. To prove the Netlify build, run npx netlify build --offline.

  5. Create the Supabase project and Google sign-in

    Do this once you have a Supabase account. Apply supabase/migrations/20261123000000_profiles.sql in the SQL editor, or with supabase db push. Then in Supabase Auth:

    • Turn on Confirm email and Confirm phone.
    • Set the minimum password length to 12 and turn on leaked-password protection.
    • Add custom SMTP so confirmation email reaches strangers.
    • Set the Site URL and the Redirect URLs to your production /console address only.
    • Turn anonymous sign-ins off and keep authenticator-app MFA on.

    In Google Cloud, create a Web application OAuth client. Use the callback address that Supabase shows as its redirect URI, and paste the client secret into Supabase only. Details are in docs/04-agent-console.md section 4.5 and supabase/README.md.

  6. Connect the repository to Netlify

    Do this once you have a Netlify account. Choose New site from Git, pick the main branch and set the publish directory to public. The build settings come from netlify.toml.

  7. Set the Netlify environment variables

    The two Supabase values are public by design. The Claude key and the GitHub token are secrets and belong to the Production context only. Put your real values where the placeholders are:

    netlify env:set ANTHROPIC_API_KEY <your-key> --context production --secret
netlify env:set GITHUB_TOKEN <your-token> --context production --secret
netlify env:set GITHUB_REPO fenago/BeachDay
netlify env:set SUPABASE_URL https://<your-project-ref>.supabase.co
netlify env:set SUPABASE_PUBLISHABLE_KEY <your-publishable-key>

    The GitHub token is fine-grained, limited to this repository, with Contents read and write and no Workflows permission. Never put the Supabase secret key or the service_role key anywhere. After you change a value, deploy again so functions see it.

  8. Turn deploy previews off

    In Site settings, open Build and deploy, then turn off Deploy Previews and branch deploys. This is required, because only production should be able to read the secrets.

  9. First deploy

    Push to main. Each production deploy costs 15 of the 300 monthly credits on the Free plan, so batch your changes. Open the site, then run the smoke check:

    BASE_URL=https://<your-site> node scripts/smoke.mjs

  10. Make yourself super_admin

    Create an account on the live site and confirm your email. Then, in the Supabase SQL editor, run supabase/manual/promote-super-admin.sql with your own user id. Use the id of a confirmed-email user only. Sign in the way you plan to sign in every day, email or Google, because they can be separate users until Supabase links them.

  11. Run the launch checks, then turn Approve on

    Approve is off by default. It stays off until the pre-launch tests (a) to (g) in docs/04-agent-console.md pass. Then change approveEnabled in netlify/functions/lib/settings.mts and deploy.

  12. Roll back if needed

    In Netlify, open Deploys, open the last good deploy, choose Publish deploy, then choose Lock to stop auto publishing. This costs 0 credits. Fix forward with git revert, then unlock. The full steps are in docs/runbooks/rollback.md.

Every link used along the way is on the Resources page.
